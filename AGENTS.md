# AGENTS.md — XYZ Mesh Correction Research & Implementation Plan

## Project Context

This is the **Kalico** codebase — a fork of Klipper 3D printer firmware.
The goal is to extend the existing Z-only bed mesh compensation into a full
**XYZ displacement correction field**, compensating for measured XY positioning
errors across the build volume in addition to Z surface height.

The user has an external calibration pipeline:
- Delta printer with modified `delta_calibrate.py` using `HEX_DENSITY=24` hex probe pattern.
- Physical XY position errors measured by probing with carbon paper, scanning
  the marks, and processing images with Python scripts.
- Each probe point's measured (true) XY is matched to its commanded XY,
  yielding a per-point `(delta_x, delta_y)` error vector.
- Current result: ~0.1mm XY RMS across the bed after kinematic calibration.
- Repeatability tests show **consistent** error patterns across trials, indicating
  systematic (correctable) error — not noise.
- Target: improve below 0.1mm RMS via in-firmware XYZ correction.

## Codebase Architecture (Verified)

### Move Transform Chain
```
GCode → skew_correction → bed_mesh → toolhead
```
Each transform exposes `.move(newpos, speed)` and `.get_position()`.
Registered via `gcode_move.set_move_transform()`.

### bed_mesh.py Key Classes
| Class | Role |
|---|---|
| `BedMesh` | Top-level; registers as move transform; owns ZMesh, MoveSplitter |
| `BedMeshCalibrate` | Generates probe grid; collects `[x_actual, y_actual, z_actual]` in `probe_finalize()` |
| `MoveSplitter` | Splits long moves into 5mm sub-segments; applies Z correction per waypoint |
| `ZMesh` | Stores probed_matrix and mesh_matrix; bilinear lookup via `calc_z(x, y)` |
| `ProfileManager` | Persists probed_matrix + params to printer.cfg |

### Probe Data Available
`probe_finalize(offsets, positions)` receives `positions` = list of
`[x_actual, y_actual, z_actual]` from `toolhead.get_position()` at trigger time.
**XY error = `x_commanded - x_actual`** — commanded grid is in `self.points`
(generated by `_generate_points()`). Currently only Z is used; XY data is discarded.

### Interpolation Methods in ZMesh
- `direct` (mesh_pps=0): raw probed values, no interpolation
- `lagrange`: 1D Lagrange polynomial per axis, capped at 6 points
- `bicubic`: separable cardinal (Catmull-Rom) splines, configurable tension

### get_position() Call Frequency
**NOT called per G1 move.** Only called via `reset_last_position()` on:
- Startup / homing / tool change / error recovery
- Firmware retraction G10/G11 (once per retract/unretract event)
- Mesh load/clear events

Adding XY correction to `get_position()` has **zero runtime cost during printing**.

### Hot Path: MoveSplitter.split()
`calc_z(x, y)` fires every 5mm of travel. Adding `calc_dx` / `calc_dy` lookups
here doubles lookup work per waypoint — negligible for bilinear grid; still
fast for TPS at N≤225 probe points on Pi 4+.

## No Existing XY Correction
| Module | What it corrects | Type |
|---|---|---|
| `skew_correction.py` | Global axis skew (XY/XZ/YZ) | Linear, global |
| `axis_twist_compensation.py` | Z probe error from X-axis twist | 1D along X or Y |
| `bed_tilt.py` | Planar bed tilt | Planar, global |
| `bed_mesh.py` | Z surface height | Spatially varying, Z-only |

**No per-point spatially-varying XY correction exists in any major FDM firmware.**

## Implementation Approaches

### Approach A — Bilinear XY Grid (Low effort, Cartesian-only)
Extend `ZMesh` to store `dx_matrix` and `dy_matrix` alongside `dz_matrix`.
Apply bilinear interpolation identically to Z correction.
- ✅ Minimal new code; reuses existing infrastructure
- ❌ Requires regular grid; C0 continuity only (kinks at cell boundaries)
- ❌ Does not handle hex/delta probe patterns

### Approach B — Thin-Plate Spline Vector Field (Recommended, all printers)
Fit TPS to scattered probe points for both Δx(x,y) and Δy(x,y) fields.
Kernel: `φ(r) = r² ln r`. Solve `(N+3)×(N+3)` system at calibration time.
Evaluate `Σ wᵢ φ(|P - Pᵢ|) + a₀ + a₁x + a₂y` at print time.
- ✅ Works with hex/delta, rectangular, adaptive patterns
- ✅ C² smooth — no cell-boundary artifacts
- ✅ Polynomial tail handles global skew as part of fit
- ✅ Numpy available in Klipper Python environment
- ✅ N=25 solve <<1ms; N=225 still negligible
- ⚠ Profile storage: N weights + control points (not a simple 2D grid)
- ⚠ get_position() inverse: one Newton step `x_gcode ≈ x_th - Δx(x_th, y_th)`

### Approach C — Kinematic Model Augmentation (Delta-specific)
Extend `delta_calibrate.py` cost function to include XY probe errors.
- ✅ Most accurate for systematic kinematic errors
- ❌ Cannot fix non-kinematic (local belt wear, pulley eccentricity) errors

### Approach D — Offline GCode Pre-distortion
Post-process GCode with the correction field before printing.
- ✅ Zero firmware change risk
- ❌ Not dynamic; no profile integration

## Recommended Implementation Plan

**Phase 1 (prototype):** Approach A — extend existing ZMesh to XYZMesh.
1. In `BedMeshCalibrate._generate_points()`, store commanded XY per point.
2. In `probe_finalize()`, pair commanded vs. actual XY; compute dx, dy per point.
3. Extend `ZMesh` (or new `XYZMesh`) to build and store `dx_matrix`, `dy_matrix`.
4. In `MoveSplitter.split()`, apply `[x + dx_correction, y + dy_correction, z + dz_correction, e]`.
5. In `BedMesh.get_position()`, subtract XY correction at current toolhead position.
6. Extend `ProfileManager` to persist dx/dy matrices.

**Phase 2 (production):** Approach B — TPS interpolation.
- Replace bilinear dx/dy lookup with TPS evaluator.
- Works naturally with `HEX_DENSITY=24` probe pattern.
- Add `algorithm: tps` option alongside existing `lagrange`/`bicubic` choices.

## Academic Background (for context)
- **CNC volumetric error compensation** (ISO 230-1, Schwenke 2008): 21 geometric
  error components for 3-axis machine; HTM-based or data-driven compensation.
- **Thin-Plate Splines** (Bookstein 1989): minimum-bending interpolant for
  scattered displacement data. Standard in metrology and robot calibration.
- **Marlin history**: 3-point → linear planar grid → bilinear ABL (~2014) → UBL
  (~2016). All Z-only. No XY correction ever implemented in mainstream FDM.
- **Klipper history**: direct → lagrange → bicubic spline interpolation added
  progressively. Z-only throughout.
